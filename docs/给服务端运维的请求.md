# 服务端修复请求

> **这份文档是给服务器管理员的。** 照着一行一行做、把指定输出发回来就行,
> 不需要理解 n2n 的原理。
>
> 上一轮收集的信息已经足够定位问题,**根因已找到**,下面只需要执行修复。

---

## 一句话结论

**服务器上没有任何进程在监听 UDP 7777,所以客户端发过去的包全部被丢弃。**

另外有一个 systemd 服务在**每 5 秒崩溃重启一次,已经空转了约 156 万次**,需要一并止住。

---

## 证据

### 1. 实际在监听的是 7654 和 8888,不是 7777

`ps` 显示有两个 supernode 进程:

```
nobody  283445  ... supernode -l 127.0.0.1:7777
nobody  303819  ... supernode -p 8888
```

但 n2n 的 `supernode` 参数含义和直觉不同(`supernode --help` 原文):

```
-p <local port>   | fixed local UDP port, defaults to 7654
-l <host:port>    | ip address or name, and port of known supernode
```

所以这两条命令的真实效果是:

| 命令 | 实际监听端口 |
|---|---|
| `supernode -l 127.0.0.1:7777` | **UDP 7654**(没给 `-p`,用了默认值) |
| `supernode -p 8888` | **UDP 8888** |

**7777 上一个进程都没有。**

### 2. `-l` 不是"监听地址"

`-l <host:port>` 的意思是"**要去联邦的另一个超级节点的地址**"。
写 `-l 127.0.0.1:7777` 等于"让这个超级节点去和 127.0.0.1:7777 上的超级节点联邦" ——
而那个端口上什么都没有。

**真正的监听端口是 `-p`。** 这个参数名确实容易误读,不是写错的人的问题。

### 3. systemd 服务在死循环重启

```
supernode.service: Main process exited, code=exited, status=254/n/a
ERROR: Bind error on local port 8888 [Address already in use]
ERROR: failed to open auxiliary TCP socket, Address already in use
supernode.service: Scheduled restart job, restart counter is at 1561738
```

服务配置的是 **8888**,而 8888 被上面那个 7 月手工启动的进程占着
(supernode 会同时占用同号的 UDP 与 TCP,`8888` 的 TCP 侧被抢了)。
于是它每 5 秒失败一次、重启一次,已经持续了约 90 天。

**这个循环本身也要停掉** —— 它一直在刷日志、耗 PID。

### 4. 服务器防火墙没问题

`firewall-cmd --list-all` 里已经放行:

```
ports: 80/tcp 7000/tcp 25565/tcp 55082/tcp 55082/udp 7777/tcp 7000/udp 7777/udp 9527/tcp
```

`7777/tcp` 和 `7777/udp` 都在。**所以本地防火墙不是障碍。**

## 要做的事

> ⚠️ **请一行一行复制执行**,不要整段粘贴。
> 上一次的输出被多行粘贴搞乱了 —— 有些行被吞掉、命令被拼接到一起。

### 第 1 步:停掉崩溃循环

```bash
systemctl stop supernode
```

```bash
systemctl disable supernode
```

### 第 2 步:清掉两个 7 月起的残留进程

```bash
pkill -f supernode
```

等 2 秒,然后确认已经清空(**应该没有任何输出**):

```bash
ps -ef | grep -i [s]upernode
```

> 如果它们又自动回来了,说明有别的程序(面板 / cron / 守护脚本)在拉起它们,
> 请告诉我是什么。

### 第 3 步:确认 7777 彻底空出来

**这两条都要跑**(supernode 会同时占 UDP 和 TCP 同号端口):

```bash
ss -ulnp | grep 7777
```

```bash
ss -tlnp | grep 7777
```

**两条都应该没有输出。** 有任何输出说明还有东西占着,请把输出发我。

### 第 4 步:找到 supernode 的实际路径

```bash
systemctl cat supernode | grep ExecStart
```

顺便把**完整的 unit 文件**也发我,我帮你改对:

```bash
systemctl cat supernode
```

### 第 5 步:启动,监听 7777

把 `/你的路径/supernode` 换成第 4 步看到的实际路径:

```bash
nohup /你的路径/supernode -p 7777 -v >> /var/log/supernode-7777.log 2>&1 &
```

### 第 6 步:验证端口绑对了(关键)

```bash
ss -ulnp | grep 7777
```

**我需要看到 `0.0.0.0:7777`。** 三种可能:

| 看到的内容 | 含义 | 怎么办 |
|---|---|---|
| `0.0.0.0:7777` | ✅ 正确 | 告诉我,我立刻测连通性 |
| `127.0.0.1:7777` | ❌ 只监听本机回环 | 把启动日志发我 |
| 没有输出 | ❌ 没起来 | 看第 7 步的日志 |

### 第 7 步:发送这两个日志

```bash
tail -n 20 /var/log/supernode-7777.log
```

```bash
journalctl -u supernode -n 5 --no-pager
```

**正常情况下应该能看到这一行:**

```
supernode is listening on UDP 7777 (main)
```

## 如果端口对了但客户端仍然连不上

那就是**阿里云安全组**的问题。

安全组是独立于服务器自身 firewalld 的一层,**从服务器内部看不到**。
需要在阿里云网页控制台 → 这台 ECS → 安全组 → **入方向** → 添加规则:

| 项 | 值 |
|---|---|
| 协议类型 | **UDP** |
| 端口范围 | **7777** |
| 授权对象(源) | `0.0.0.0/0` |
| 优先级 | 1 |

> **这一条是最容易漏的。** 常见误区是"服务器上 `-p 7777` 起来了就该通" ——
> 不对,安全组不放行的话包在到达服务器网卡之前就被丢了。
>
> 顺带:**如果希望 frp 的映射端口能从公网访问,那些端口也要在安全组里放行**
> (比如映射了 25565,就需要 TCP 25565)。

## 另外:三个安全问题(与本次故障无关,但建议处理)

这些在服务器上比较显眼,顺手提一下,你自己判断要不要处理。

### ① SSH 正在被暴力破解

登录提示:

```
There were 24467 failed login attempts since the last successful login
Last failed login: Sat Oct 17 13:19:05 CST 2026 from 113.44.52.136 on ssh:notty
```

**一天之内 2.4 万次失败登录。** 而且当前是 **root + 密码**登录 SSH,
这正是爆破最主要的目标。

建议(任选):
- 改用密钥登录,关闭密码登录
- 至少禁止 root 直接用密码登录:
  ```
  PermitRootLogin prohibit-password
  ```
- 安装 fail2ban 自动封禁

### ② 有 1 个严重级安全更新未打

```
110 Security notice(s)
      1 Critical Security notice(s)
```

### ③ 开放端口偏多

```
80/tcp 7000/tcp 25565/tcp 55082/tcp 55082/udp 7777/tcp 7000/udp 7777/udp 9527/tcp
```

`55082`、`9527` 如果不是有意开的,建议关掉。

## 附:两条之前提过的安全请求(需要你决定)

### 换掉 frp 的 token

那个 token 已经在多处文件和聊天记录里出现过。虽然我在上传代码前把所有出现它的地方
都清掉了,但这个值本身早就不算秘密了。

改完告诉我新值,我在客户端更新。

### 换掉 n2n 的组名

现在的组名只有 **2 个字符**。

n2n 组的是**二层**网络 —— 进去的人等于插在同一根网线上,能看到彼此的 ARP
和广播流量,以及任何未加密的局域网服务。组名 + 密码就是唯一的门钥匙。

建议换成 12 位以上的随机串。**所有组员必须用同一个值**,否则彼此发现不了,
所以最好由你定下来统一通知。

## 附:为什么之前一直连不上(给好奇的人)

n2n 的客户端(edge)连超级节点的过程是:

```
edge  ──UDP 注册包──►  39.105.139.45:7777
                          │
                          ├─ firewalld 放行了 7777/udp  ✅
                          ├─ 阿里云安全组(未知)
                          └─ 有没有进程在 7777 上监听?  ❌ 没有
                                ↓
                       包被丢弃,edge 一直等回包
                                ↓
              "WARNING: supernode not responding"
```

客户端侧我已经逐一排除了:DNS 解析、TAP 网卡、参数传递、密钥、本地拦截。
并且在本机起了一个超级节点做对照 —— **握手成功**
(`[OK] edge <<< ================ >>> supernode`),
所以客户端本身是好的。

差的就是服务器上那个 7777。
