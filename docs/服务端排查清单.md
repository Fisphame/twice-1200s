# 服务端排查清单(超级节点)

## 结论(2026-10-12 已确认)

**客户端完全正常,问题在服务端。**

证据是两条独立路径都指向同一结论:

| 途径 | 结果 |
|---|---|
| **本机回环验证** | ✅ 通过。完整握手:`Rx REGISTER_SUPER_ACK` → `[OK] edge <<< ================ >>> supernode` |
| **连远端超级节点** | ❌ 失败。反复 `WARNING: supernode not responding` |

同一个 edge.exe、同一块网卡、同一套参数、同一个密码,**唯一的差别是超级节点地址**。
本机能通说明客户端没问题;所以 `1200s.top:7777` 沉默是服务端现象。

**已排除的客户端侧原因:** DNS 解析、TAP 网卡、参数传递、密钥、本地 UDP 拦截。

## 需要你在云控制台上确认的事

服务器地址 `39.105.139.45`,域名 `1200s.top` 指向它。
**同一台机器的 TCP 7000 端口(frps)是可达的**,所以服务器本身在线 ——
问题局限在 supernode 的 UDP 7777 上。

### 1. supernode 进程在运行吗?

```
检查:进程列表里有没有 supernode
```

如果不在运行,这就是原因。启动它的命令(binary 在项目的 `assets/n2n/` 里):

```bash
# Linux 上(服务器大概率是 Linux)
./supernode -p 7777 -v
```

**注意 `-v` 不是可选的美化选项**:实测确认 supernode 在没有参数时
只会打印帮助然后退出。

**建议挂起来并记日志**,否则你的终端一断它就跟着没了:

```bash
nohup ./supernode -p 7777 -v >> /var/log/supernode.log 2>&1 &
```

或者用 systemd 做成服务(推荐,能开机自启和自动重启)。

### 2. UDP 7777 在安全组里放行了吗?

```
检查:云厂商控制台的「安全组 / 防火墙」规则
需要:UDP 7777 入方向放行(来源 0.0.0.0/0 或你们的出口 IP 段)
```

**这一条最容易漏。** 常见的错觉是"我 `-p 7777` 启动了就应该通",
但云厂商的安全组是独立于服务器防火墙的一层,不放行的话
包在到达服务器之前就被丢弃了 —— 现象正是 edge 看到的"无回包"。

顺带确认服务器自己的防火墙(ufw / firewalld / iptables)也没拦:

```bash
# 常见发行版
sudo ufw status                 # Ubuntu/Debian
sudo firewall-cmd --list-all    # CentOS/RHEL
```

### 3. 端口真的在监听吗?

```
检查:ss -ulnp | grep 7777      (或 netstat -ulnp | grep 7777)
期望:看到 supernode 在 0.0.0.0:7777 上监听
```

如果显示的是 `127.0.0.1:7777`,那它只监听了本机回环,
外部连不上 —— 需要改成监听所有接口。

### 4. 从你这边做一次验证(不需要登服务器)

如果上面三条都确认没问题但仍然连不上,在**你本机**做这次对照:

## 一个需要说明的配置问题:组名太短

当前配置里:

```json
"community": "12",
```

**组名只有 2 个字符。** 体检会给出"组名偏短"的警告。这不只是形式问题:

n2n 的入网凭据就是 **「组名 + 密码」**,而 n2n 组的是**二层**网络 ——
进去的人等于插在同一根网线上,能看到你的 ARP 与广播流量,
以及你机器上任何未加密的局域网服务。

**两个字符的组名加上一个 9 位密码,被猜中的概率不低。** 建议换成 12 位以上的随机串:

```powershell
$f = "$env:APPDATA\Twice1200\config.json"
$j = Get-Content $f -Raw -Encoding UTF8 | ConvertFrom-Json
$j.n2n.community = '换成12位以上的随机串'
$j | ConvertTo-Json -Depth 10 | Set-Content $f -Encoding UTF8
```

**所有组员必须用同一个值**,否则彼此发现不了。

## 服务端的两条环境警告(与故障无关,但值得知道)

第一条来自 `supernode.exe` 自己的输出:

```
WARNING: using default federation name; FOR TESTING ONLY,
usage of a custom federation name (-F) is highly recommended!
```

联邦名默认值属于"公开的默认配置",建议启动时用 `-F` 指定一个自己的值。

第二条:随包分发的 n2n 是 **v3.1.0(2022-02-28 构建)**。
如果服务器上跑的是别的版本,联邦/协议细节可能不匹配。
**服务端与客户端最好用同一份二进制** —— 项目 `assets/n2n/` 里的那份
已经验证过能与自身正常通信,直接拿上去用最省事。
